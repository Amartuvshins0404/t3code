# Codemap

A thread's details panel has a Code map row. It opens a right-panel tab with an area map of the repository where the parts the thread touched light up. This page records why it is built the way it is.

## Decisions

| Choice                                                                                                                                       | Why                                                                                                                                     | Rejected                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Area map (treemap): boxes sized by lines of code, no lines between boxes, two levels at a time, click to zoom                                | It answers "where in the codebase did this thread work" at a glance, on any repo.                                                       | A node-and-arrow graph: too busy to read during a turn. An impact graph: no sense of location. Layer bands: guessing layers fails on many repos. |
| Lives in a thread, not on the project page                                                                                                   | The question is always about one thread's work.                                                                                         | A project-wide Map view next to the board.                                                                                                       |
| Extraction on the server, from git's file list, package manifests and line counts                                                            | Works on any repo with no build or install. Clients receive only the boxes they draw, so remote and tunnel connections behave the same. | Tree-sitter, language servers, SCIP: a toolchain or large download per language.                                                                 |
| The map reads the thread's own workspace (its worktree), cached by HEAD plus working-tree status                                             | New files appear as real boxes. A second open is instant.                                                                               | Reading only the project root: a worktree thread's new files would be missing.                                                                   |
| Changed files come from the thread's checkpoints; "new" comes from `git diff --name-status` between the thread's first and latest checkpoint | Checkpoint files already drop imported commits, and their kind is always `modified`, so the add/modify split needs the refs.            | Downloading the full thread patch to the client to read file headers.                                                                            |
| The server always keeps touched parts in the view, and the client gives lit boxes a minimum area                                             | A small new folder inside a large package would otherwise be cut by the size limit or drawn too small to see.                           | —                                                                                                                                                |
| Only the smallest lit box is filled; lit parents get a coloured frame                                                                        | A filled parent covers everything inside it and hides where the change is.                                                              | —                                                                                                                                                |
| Clicking a changed file opens the existing Diff tab on the latest turn that touched it                                                       | Reuses the diff view people already know.                                                                                               | A second before/after viewer inside the map.                                                                                                     |

## Slices

1. Area map with changed (amber) and new (green) parts, live after each turn.
2. Planned parts (dashed): the agent declares the parts it intends to touch, likely through an MCP tool, before it edits.

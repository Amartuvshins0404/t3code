# Codemap

A thread's details panel has a Code map row. It opens a right-panel tab that shows what the thread changed: a change map by default, and an area map of the whole repository behind a toggle. This page records why it is built the way it is.

## Decisions

| Choice                                                                                                                                                                                                                                                                                               | Why                                                                                                                                                                                                                                                                                                                                                      | Rejected                                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The default view shows only changed files, boxes sized by lines added plus removed, grouped into frames by package (or top folder) or by kind                                                                                                                                                        | The question is "what did this thread change, how big, where". Sizing the whole repo by lines of code put the eye on big untouched folders.                                                                                                                                                                                                              | A treemap of the whole repo as the default. A node-and-arrow graph: too busy, and it needs an import scanner. A plain list: no sense of size or shape. |
| New, changed, moved and deleted get their own colours; generated and lock files are hidden behind a button                                                                                                                                                                                           | A rewrite and a one-line edit must not look the same, and a lockfile must not be the biggest box.                                                                                                                                                                                                                                                        | Two states (new, changed) only.                                                                                                                        |
| Small files fold into one "N more" box per frame, coloured by the mix of what is inside; at most 8 frames, the rest go to "Other places"                                                                                                                                                             | A 400-file change stays a few readable boxes instead of confetti; every file stays reachable from the list under the map.                                                                                                                                                                                                                                | A minimum box size for every file: unreadable on large changes.                                                                                        |
| Plain-word lines and risk flags (database, packages, deleted files, env or CI files, no tests) come from file paths in the client                                                                                                                                                                    | They cost nothing, need no model call, and work on any repo.                                                                                                                                                                                                                                                                                             | A model-written summary per group: slow, costs money, and the map must work without it.                                                                |
| A tree-level `git diff --raw --find-renames` between the thread's baseline and latest checkpoint picks the files the thread's checkpoints list and pairs moves; line counts then come from `--numstat` on those files only, each move's two paths in the same batch, batches under 24,000 characters | Checkpoints keep only a moved file's new path, so the pairing must happen on the whole tree. The tree pass skips file contents, so it stays near a second even across a 28k-file merge, and files only a pull touched stay out. Lines a pull added to a file the thread also edited are still counted. Windows caps a command line at 32,767 characters. | Summing checkpoint file stats in the client: checkpoint kinds are always `modified`, so new, deleted and moved files cannot be told apart.             |
| "Last edits" diffs the last checkpoint that changed files against the one before it                                                                                                                                                                                                                  | A last turn that only talked would otherwise show an empty map.                                                                                                                                                                                                                                                                                          | —                                                                                                                                                      |
| Extraction for the whole-repo view runs on the server from git's file list, package manifests and line counts, with each file lstat-ed first: regular files up to 1 MB, at most 100k files, no import scanning                                                                                       | Works on any repo with no toolchain; untracked files can be symlinks or huge dumps, and the work runs on the server event loop.                                                                                                                                                                                                                          | Tree-sitter, language servers, SCIP. A worker process.                                                                                                 |
| The map reads the thread's own workspace (its worktree), cached by HEAD plus working-tree status                                                                                                                                                                                                     | New files appear as real boxes. A second open is instant.                                                                                                                                                                                                                                                                                                | Reading only the project root.                                                                                                                         |
| Clicking a changed file opens the existing Diff tab on the latest turn that touched it                                                                                                                                                                                                               | Reuses the diff view people already know.                                                                                                                                                                                                                                                                                                                | A second before/after viewer inside the map.                                                                                                           |
